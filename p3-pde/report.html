spectral — Fourier pseudo-spectral, 3/2 de-aliasing, integrating-factor RK4

Algebraic slope (all 6 grids): 9.1575 — not meaningful, and the script says so: pairwise orders strictly increase (4.73, 8.25, 11.83, 15.07, 18.41), the exact signature of convergence faster than any fixed power of N. The metric that applies is the exponential rate c = 0.0524 in err ~ C*exp(-c*N). dt_halving_relative_change_finest = 9.24e-04 confirms the fixed dt=1e-4 RK4 time-stepping (diffusion handled exactly via integrating factor) is not the error bottleneck at the finest grid.

3. Caveats

  1. Fit-window inconsistency across scripts. finite-difference and finite-element fit observed_order on the finest 3 grids; finite-volume fits on all 5; pinn fits on all 3; spectral's algebraic slope uses all 6 (but is explicitly disclaimed). Raw observed_order values are therefore not directly comparable across methods without knowing the fit window — see the finite-volume recomputation above.
  2. Error norms differ by construction. finite-difference and spectral compare point values on the grid; finite-element uses 5-point Gauss quadrature per element; finite-volume compares cell averages via a closed-form exact integral. Each method's own order (rate of decrease) is exact; cross-method error magnitudes at similar grid counts are only an approximate comparison.
  3. pinn's "grids" are collocation counts, not a mesh. grids_meaning in the JSON says so directly; size_abscissa converts to a mean spacing h = sqrt(2*pi*0.5/N_c) for plotting only, and it is a rough proxy since pinn error is training-limited, not sampling-limited.
  4. pinn width is confounded with collocation count (32→64→128 alongside 2000→8000→32000), so its three data points vary two things at once.
  5. Time-step counts reflect a CFL/diffusion crossover, not a bug. In finite-difference and finite-volume, time_steps roughly doubles at coarse grids (advective CFL, dt~h) then roughly quadruples at fine grids (diffusive limit, dt~h^2) as the dt = min(...) constraint switches which term binds.
  6. No script was re-run for this report. Every number above is read from the five *-order.json files; the one flagged exception is the finite-volume finest-3 order (1.9126), which is a direct np.polyfit recomputation on that JSON's own grids/errors arrays, not a re-simulation.
